# SSD 测试平台 — 详细日志生成与工具可移植性说明

> 适用版本：ssd_test_tool v1.9.3（模块化重构版）
> 目标平台：Ubuntu 22.04 LTS x86_64，Python 3.10.12
> 文档日期：2026-09-30

---

## 1. 概述

本文档说明 SSD 测试平台（模块化版）的**详细日志生成机制**和**工具可移植性设计**，确保工具在任意部署路径下都能正常启动、自动生成报告和日志文件。

核心设计原则：**所有路径基于 `__file__` 动态计算，不硬编码任何绝对路径，目录不存在时自动创建。**

## 2. 详细日志生成机制

### 2.1 默认日志目录

默认日志目录为 `ssd_test_tool/logs/`，基于 `common.py` 的位置动态计算：

```python
# ssd_test_tool/common.py
def get_default_log_dir() -> str:
    script_dir = os.path.dirname(os.path.abspath(__file__))
    return os.path.join(script_dir, "logs")
```

- `__file__` = `ssd_test_tool/common.py`
- `script_dir` = `ssd_test_tool/`（无论项目部署在哪个路径）
- 返回值 = `ssd_test_tool/logs/` 的**绝对路径**

### 2.2 日志文件命名规则

| 日志类型 | 命名格式 | 示例 |
|---------|---------|------|
| SSD 测试主日志 | `ssd_test_YYYYMMDD_HHMMSS.log` | `ssd_test_20260929_143752.log` |
| OSINT 测试结果 | `osint_results_YYYYMMDD_HHMMSS.json` | `osint_results_20260929_145809.json` |
| JSON 测试报告 | `ssd_test_report_YYYYMMDD_HHMMSS.json` | `ssd_test_report_20260929_143759.json` |
| 功耗测试 Log | 与 JSON 同名，后缀改为 `.log` | `power_report_20260929.log` |

时间戳为日志创建时的本地时间，精确到秒。

### 2.3 日志内容格式

每行日志的格式为：

```
[YYYY-MM-DD HH:MM:SS] [LEVEL] Message content
```

示例：
```
[2026-09-29 14:37:52] [INFO] =======================================================
[2026-09-29 14:37:52] [INFO]   SSD Automated Test Script v1.9.3
[2026-09-29 14:37:52] [INFO]   Device: /dev/nvme0n1 (type: nvme)
[2026-09-29 14:37:52] [WARNING]   Media errors count > 0 (5353), WARNING only
```

### 2.4 日志级别

| 级别 | 用途 | 控制台输出 | 文件输出 |
|------|------|----------|---------|
| `DEBUG` | 调试细节（命令输出、中间变量） | `-v` 参数时显示 | 始终记录 |
| `INFO` | 正常流程信息 | 始终显示 | 始终记录 |
| `WARNING` | 警告信息（不影响测试继续） | 始终显示 | 始终记录 |
| `ERROR` | 错误信息（测试项失败） | 始终显示 | 始终记录 |

### 2.5 日志输出位置

日志同时输出到两个地方：
1. **控制台（stdout）**：实时显示测试进度
2. **文件**：写入 `ssd_test_tool/logs/ssd_test_*.log`

### 2.6 详细日志的语言

- **详细日志固定为纯英文输出**，不随 GUI 语言切换而改变
- 所有测试项目（固件/SMART/容量/性能/电源循环/SPOR/OSINT/读写/功耗）的日志消息、结果摘要、错误提示均为英文
- 确保日志文件可在英文环境下正常阅读和归档

### 2.7 日志初始化流程

```python
# ssd_test_tool/common.py
def setup_logging(log_dir: str, verbose: bool = False):
    log_dir = resolve_log_dir(log_dir)       # 解析为绝对路径
    os.makedirs(log_dir, exist_ok=True)       # 目录不存在时自动创建
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    log_file = os.path.join(log_dir, f"ssd_test_{timestamp}.log")
    # ... 创建 logger、控制台 handler、文件 handler
    return logger, log_file
```

关键点：
- `resolve_log_dir()` 将相对路径基于包位置解析，**而非当前工作目录**
- `os.makedirs(exist_ok=True)` 确保日志目录不存在时自动创建
- 日志文件路径为绝对路径，不受 cwd 影响

## 3. 工具可移植性设计

### 3.1 路径设计原则

模块化版本中**没有任何硬编码的绝对路径**，所有路径均基于 `__file__` 动态计算：

| 路径 | 计算方式 | 所在文件 |
|------|---------|---------|
| 包根目录 | `os.path.dirname(os.path.abspath(__file__))` | `main.py` |
| 默认报告目录 | `os.path.join(_PACKAGE_ROOT, "reports")` | `main.py` |
| 默认日志目录 | `os.path.join(os.path.dirname(__file__), "logs")` | `common.py` |
| GUI 包根目录 | `os.path.dirname(os.path.dirname(os.path.abspath(__file__)))` | `gui/main_window.py` |
| oscill 启动 cwd | `os.path.dirname(os.path.dirname(os.path.abspath(__file__)))` | `testers/power.py` |

### 3.2 任意路径启动方法

#### 方式1：cd 到项目根目录（推荐）

```bash
# 假设项目部署在 /opt/my_ssd_tool/oscill-0.1.0-linux/
cd /opt/my_ssd_tool/oscill-0.1.0-linux
python3 -m ssd_test_tool.main --gui
```

#### 方式2：设置 PYTHONPATH（不 cd 也能启动）

```bash
export PYTHONPATH=/opt/my_ssd_tool/oscill-0.1.0-linux:$PYTHONPATH
python3 -m ssd_test_tool.main --gui
```

#### 目录结构要求

必须保持以下结构完整：

```
<任意路径>/oscill-0.1.0-linux/    ← 项目根目录（在此执行命令）
└── ssd_test_tool/                  ← 包目录（名称不可改）
    ├── __init__.py
    ├── main.py
    ├── common.py
    ├── i18n/
    ├── testers/
    ├── gui/
    ├── oscill/
    ├── reports/                     ← 自动创建
    └── logs/                        ← 自动创建
```

### 3.3 报告与日志自动生成位置

无论项目部署在哪个路径，报告和日志都会自动生成到对应位置：

| 产物 | 生成位置 | 自动创建 |
|------|---------|---------|
| SSD 测试 JSON 报告 | `<项目路径>/ssd_test_tool/reports/` | 是 |
| SSD 详细日志 | `<项目路径>/ssd_test_tool/logs/` | 是 |
| oscill 自动导出 JSON | `<项目路径>/ssd_test_tool/reports/` | 是（oscill 内部） |
| JSON 转 Log 文件 | `<项目路径>/ssd_test_tool/reports/` | 是 |
| OSINT 结果 JSON | `<项目路径>/ssd_test_tool/logs/` | 是 |

### 3.4 oscill 子模块的路径处理

oscill 作为 `ssd_test_tool` 的子包，启动时通过环境变量传递配置：

```python
# ssd_test_tool/testers/power.py
script_dir = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
# script_dir = ssd_test_tool/（动态计算）

env["OSCILL_AUTO_JSON_DIR"] = os.path.abspath(self.cfg.output_dir)
# output_dir 默认 = ssd_test_tool/reports/（动态计算）

cmd = [sys.executable, "-m", "oscill.gui"]
proc = subprocess.Popen(cmd, cwd=script_dir, env=env)
# cwd = ssd_test_tool/，确保 oscill 能作为顶层模块导入
```

oscill 内部接收 `OSCILL_AUTO_JSON_DIR` 环境变量：
```python
# ssd_test_tool/oscill/gui.py
auto_json_dir = os.environ.get("OSCILL_AUTO_JSON_DIR", "")
os.makedirs(auto_json_dir, exist_ok=True)  # 目录不存在自动创建
filepath = os.path.join(auto_json_dir, filename)
```

## 4. 路径配置指南

### 4.1 默认路径一览

| 配置项 | 默认值 | 说明 |
|--------|-------|------|
| 报告输出目录 | `ssd_test_tool/reports/` | 所有 JSON 报告统一输出 |
| 日志输出目录 | `ssd_test_tool/logs/` | 所有 .log 文件统一输出 |
| oscill JSON 导出目录 | 同报告输出目录 | 通过 `OSCILL_AUTO_JSON_DIR` 传递 |

### 4.2 GUI 中修改路径

在 SSD 测试平台 GUI 的"通用设置"区域：
- **报告输出目录**：输入框可手动修改，支持浏览选择
- **日志输出目录**：输入框可手动修改，支持浏览选择

修改后立即生效，后续测试将使用新路径。

### 4.3 CLI 参数指定路径

```bash
# 指定报告输出目录
sudo python3 -m ssd_test_tool.main -d /dev/nvme0n1 -t all \
    -o /custom/path/to/reports -y

# 指定日志输出目录
sudo python3 -m ssd_test_tool.main -d /dev/nvme0n1 -t all \
    --log-dir /custom/path/to/logs -y
```

> 传入相对路径时，基于 `ssd_test_tool/` 包位置解析，而非当前工作目录。

### 4.4 功耗测试 JSON 路径

功耗测试有两个相关路径：
1. **自动导出目录**：由"报告输出目录"决定，oscill 自动导出 JSON 到此目录
2. **手动转换输入**：GUI 中"JSON 报告路径"输入框，用于手动选择已有 JSON 文件进行转换

> 手动转换输入框默认为空，需要用户浏览选择；不影响 oscill 自动导出路径。

## 5. 目录自动创建机制

所有输出目录在使用前都会自动创建，无需手动建立：

| 创建位置 | 代码 | 时机 |
|---------|------|------|
| 日志目录 | `os.makedirs(log_dir, exist_ok=True)` | `setup_logging()` 调用时 |
| 报告目录 | `os.makedirs(output_dir, exist_ok=True)` | 生成 JSON 报告前 |
| oscill JSON 目录 | `os.makedirs(auto_json_dir, exist_ok=True)` | oscill 导出 JSON 前 |

`exist_ok=True` 确保目录已存在时不会报错。

## 6. 常见问题排查

### Q1：启动报 `ModuleNotFoundError: No module named 'ssd_test_tool'`

**原因**：没有在项目根目录下执行命令，Python 找不到 `ssd_test_tool` 包。

**解决**：
```bash
cd /你的/项目/路径/oscill-0.1.0-linux
python3 -m ssd_test_tool.main --gui
```

或设置 `PYTHONPATH`：
```bash
export PYTHONPATH=/你的/项目/路径/oscill-0.1.0-linux:$PYTHONPATH
python3 -m ssd_test_tool.main --gui
```

### Q2：日志文件没有生成

**排查步骤**：
1. 确认 `ssd_test_tool/logs/` 目录是否存在（不存在时应自动创建）
2. 检查是否有权限写入该目录
3. 查看控制台输出是否有报错
4. 确认 `--log-dir` 参数是否指定了不可写的路径

### Q3：oscill 自动导出的 JSON 找不到

**排查步骤**：
1. 确认 `ssd_test_tool/reports/` 目录是否存在
2. 查看 oscill 窗口日志是否显示 `JSON reports will be auto-exported to: <路径>`
3. 确认在 oscill 中点击了"开始连续测量"
4. 确认采集完成后 oscill 状态显示"测试已完成"
5. 检查报告文件名格式：`power_*_combined.json` 或类似

### Q4：把项目复制到其他路径后，报告路径还是旧路径

**原因**：GUI 配置可能保存在配置文件中，覆盖了默认值。

**解决**：在 GUI 的"报告输出目录"输入框中手动修改为新路径，或删除配置文件恢复默认。

### Q5：相对路径是基于哪个目录解析的

**答案**：所有相对路径都基于 `ssd_test_tool/` 包所在目录解析，**而非当前工作目录（cwd）**。

例如：
- 在 `/home/user/` 下执行 `cd /home/user/ && python3 -m ssd_test_tool.main -o ./my_reports`
- 报告实际生成在 `<项目路径>/ssd_test_tool/my_reports/`，而非 `/home/user/my_reports/`

### Q6：可以把 reports 和 logs 目录放到项目外面吗

**可以**。在 GUI 中输入绝对路径，或使用 CLI 参数：
```bash
python3 -m ssd_test_tool.main -d /dev/nvme0n1 -t all \
    -o /data/ssd_reports --log-dir /data/ssd_logs -y
```

## 8. 技术实现摘要

### 8.1 关键代码位置

| 功能 | 文件 | 函数/变量 |
|------|------|----------|
| 默认报告目录 | `main.py` | `_PACKAGE_ROOT`, `_DEFAULT_REPORT_DIR` |
| 默认日志目录 | `common.py` | `get_default_log_dir()` |
| 路径解析 | `common.py` | `resolve_log_dir()` |
| 日志初始化 | `common.py` | `setup_logging()` |
| GUI 报告路径 | `gui/main_window.py` | `self._ssd_test_tool_root` |
| oscill JSON 目录 | `testers/power.py` | `OSCILL_AUTO_JSON_DIR` |
| oscill 内部导出 | `oscill/gui.py` | `_auto_json_dir`, `_save_auto_json()` |

### 8.2 设计原则

1. **零硬编码路径**：代码中不出现任何 `/home/...` 形式的绝对路径
2. **基于 `__file__` 动态计算**：所有默认路径基于模块文件位置计算
3. **相对路径安全解析**：相对路径基于包位置解析，不受 cwd 影响
4. **目录自动创建**：所有输出目录使用 `os.makedirs(exist_ok=True)` 自动创建
5. **子模块通过环境变量传参**：oscill 的配置通过环境变量传递，不依赖硬编码路径
