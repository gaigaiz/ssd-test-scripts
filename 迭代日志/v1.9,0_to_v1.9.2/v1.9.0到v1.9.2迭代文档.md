# SSD 测试工具 v1.9.0 → v1.9.2 迭代文档

> 版本：v1.9.2 | 更新日期：2026-09-23 | 基线版本：v1.9.1

---

**注意事项：这里忽略V1.9.0→ v1.9.1的迭代说明（因为v1.9.0与v1.9.1之间只修改了正常电源循环的代码功能，详情查看代码修改说明即可）**

## 1. 版本概述

v1.9.2 是对 SSD 性能测试工具的重大升级，核心目标是**让 SSD 真正进入 FOB 和稳态状态**，并在 GUI 上位机中提供状态可视化与手动控制能力。

### 1.1 解决的核心问题

| 问题 | v1.9.1 现状 | v1.9.2 改进 |
|------|------------|------------|
| FOB 进入不可靠 | 使用 `blkdiscard`（仅发 TRIM），失败仅 warning 继续 | 使用 `nvme format --ses=1`（User Data Erase），失败回退 blkdiscard |
| 稳态无检测算法 | 固定写入量（顺序写2遍+随机写2X容量+等300s），无法证明达到稳态 | 实现 SNIA SSS PTS v2.0.2 规范的 WIPC+WDPC 多轮循环 + 5轮滑动窗口稳态检测 |
| 状态不可见 | GUI 无法知道 SSD 当前处于什么状态 | 新增 SSD 状态面板（FOB/Steady/Unknown），按设备序列号持久化 |
| 状态不可控 | 无法手动让 SSD 进入指定状态 | 新增"进入 FOB"/"进入稳态"/"重置 Unknown"按钮 |
| 测试与状态脱节 | 性能测试不关心 SSD 当前状态 | 开始测试时三分支状态校验逻辑 |
| SMART 误报 | 介质错误 5353 导致健康检查失败 | 可配置忽视指定介质错误号（默认 5353） |

## 2. 核心功能变更

### 2.1 FOB 状态进入改造

#### 擦除方式变更

```
v1.9.1: blkdiscard /dev/nvme0n1  (仅 TRIM，不等同于 NVMe Format)
v1.9.2: sudo nvme format /dev/nvme0n1 --namespace-id=1 --ses=1  (User Data Erase)
        失败时自动回退 blkdiscard
```

#### 新增方法

- `PerformanceTester._nvme_purge()` — NVMe User Data Erase 擦除，返回 `(success, method)`
- 支持 `--purge-method auto|user-data|blkdiscard` 命令行参数
- `run_fob_test()` 中新增 `precondition` 检查，状态一致时可跳过擦除

#### 状态持久化

- 状态文件：`~/.ssd_test_state.json`
- 按设备序列号隔离，支持多设备
- 字段：`state`（fob/steady/unknown）、`serial`、`timestamp`、`device`

### 2.2 稳态预处理改造（SNIA SSS PTS v2.0.2 合规）

#### 算法流程

```
WIPC (Write/Initialize/Prepare Conditioning)
  └─ 顺序写 2 遍全盘（128K 顺序写）

WDPC (Write/Deterministic/Prepare Conditioning)
  └─ 多轮循环，每轮包含 3 个跟踪变量测试点：
      1. RND4K 写 (Q32T1)
      2. RND64K 混合 65%读/35%写 (Q4T1)
      3. RND1024K 读 (Q1T1)
  └─ 每点默认 60 秒，可配置

稳态检测（5轮滑动窗口）
  ├─ Range ≤ 20% × Ave
  ├─ |Slope| ≤ 10% × Ave
  └─ 3 个跟踪变量同时满足才判定稳态
  └─ 最多 25 轮，未达标则降级继续
```

#### 新增方法

- `PerformanceTester.precondition_steady_state()` — 完整稳态预处理入口
- `PerformanceTester._run_wdpc_round()` — 执行单轮 WDPC
- `PerformanceTester.check_steady_state()` — 5轮滑动窗口稳态判定
- `PerformanceTester.check_all_tracking_vars()` — 3跟踪变量同时判定
- 常量：`STEADY_TRACKING_VARS`、`STEADY_MAX_ROUNDS=25`、`STEADY_POINT_DURATION=60`

#### 命令行参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--steady-max-rounds` | 25 | WDPC 最大轮数 |
| `--steady-point-duration` | 60 | 每个测试点时长（秒） |

### 2.3 GUI SSD 状态控制面板

#### 布局

性能标签页顶部左右两栏布局：

```
┌─────────────────────────┬─────────────────────────┐
│   SSD 状态控制           │   批量任务排队           │
│   当前状态: [FOB] 彩色标签│   备注: [____] [+新增]  │
│   序列号: 64400003       │   [任务列表]            │
│   [进入FOB][进入稳态]    │   [↑][↓][删除][清空]   │
│   [刷新][重置Unknown]    │   [导出JSON] 共N组任务  │
└─────────────────────────┴─────────────────────────┘
```

#### 状态标签颜色

| 状态 | 颜色 |
|------|------|
| FOB | 蓝色 |
| Steady | 绿色 |
| Unknown | 灰色 |

#### 手动状态切换

- **进入 FOB**：调用子进程执行 `--action enter-fob`，完成后自动刷新状态
- **进入稳态**：调用子进程执行 `--action enter-steady`，完成后自动刷新状态
- **刷新**：从状态文件重新读取当前状态
- **重置 Unknown**：清除状态文件，恢复 Unknown

### 2.4 开始测试三分支状态逻辑

```
点击"开始测试"
    │
    ├─ 目标状态 = Unknown
    │   └─ 直接进行性能测试，不进入任何状态
    │
    ├─ 当前状态 = 目标状态（一致）
    │   └─ 设置 _skip_precondition=True
    │      命令行加 --no-precondition
    │      直接进行性能测试（不重复擦除/预处理）
    │
    └─ 当前状态 ≠ 目标状态（不一致）
        └─ 弹出警告对话框
           ├─ 选"是" → 自动进入目标状态 → 完成后自动开始性能测试
           └─ 选"否" → 取消测试，用户手动控制状态后重试
```

### 2.5 SMART 健康检查增强

- 新增 `PerformanceTester._check_smart_health()` 方法
- 支持 `--smart-ignore-media-errors` 参数（默认 `"5353"`）
- 可配置多个错误号，逗号分隔
- 忽视的错误在日志中标注但不判定为失败

### 2.6 目标状态选项变更

```
v1.9.1: 测试状态 = FOB / Steady / Both（先FOB后Steady批量测试）
v1.9.2: 目标状态 = FOB / Steady / Unknown（默认 Unknown 直接测试）
```

- `PERF_UNKNOWN = "unknown"` 新增常量
- Unknown 状态下直接执行 `run_full_perf_test("Unknown")`，不进行任何预处理
- GUI 下拉框、命令行 argparse、TestConfig 默认值全部同步更新

## 3. 命令行接口变更

### 3.1 新增参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--action` | `run-tests` | 操作模式：`run-tests`/`enter-fob`/`enter-steady`/`status` |
| `--purge-method` | `auto` | FOB 擦除方式：`auto`/`user-data`/`blkdiscard` |
| `--steady-max-rounds` | 25 | 稳态 WDPC 最大轮数 |
| `--steady-point-duration` | 60 | 稳态每个测试点时长（秒） |
| `--smart-ignore-media-errors` | `5353` | SMART 忽视的介质错误号 |
| `--no-precondition` | False | 跳过预处理（状态一致时自动添加） |

### 3.2 修改参数

| 参数 | v1.9.1 | v1.9.2 |
|------|--------|--------|
| `--perf-state` | choices=fob/steady/both, default=both | choices=fob/steady/unknown, default=unknown |

### 3.3 新增操作模式

```bash
# 进入 FOB 状态
sudo python3 ssd_test_v1.9.2.py -d /dev/nvme0n1 --action enter-fob -y

# 进入稳态
sudo python3 ssd_test_v1.9.2.py -d /dev/nvme0n1 --action enter-steady -y

# 查看当前状态
python3 ssd_test_v1.9.2.py -d /dev/nvme0n1 --action status
```

## 4. Bug 修复记录

| 编号 | 问题描述 | 根因 | 修复方式 |
|------|---------|------|---------|
| BUG-01 | 进入 FOB 状态失败（退出码2） | GUI 硬编码脚本路径 `~/max_tool/`，root 用户下 `~` 解析为 `/root`，实际脚本在 `/home/test/max_tool/` | 改为 `os.path.abspath(__file__)` 动态获取路径 |
| BUG-02 | 性能测试无法生成详细日志 | 同上（脚本找不到，根本没运行）；fio `--output-format=json+` 旧版不兼容 | 修复路径；fio 改为 `json` 格式；日志目录改为基于脚本目录的绝对路径 |
| BUG-03 | 全局异常无 Traceback | `if __name__ == "__main__"` 无异常捕获 | 添加 try/except 包装，输出完整 Traceback 到 stderr |
| BUG-04 | FOB 状态一致时仍重复擦除 | `run_fob_test()` 无条件执行 `_nvme_purge()` | 添加 `if self.cfg.precondition:` 检查；GUI 状态一致时设置 `_skip_precondition=True` |
| BUG-05 | 状态栏不重置 | `_reset_ui_state()` 只重置按钮，不重置 `status_var` 和进度条 | 添加状态栏重置为"就绪"、进度条重置为0 |
| BUG-06 | GUI 日志隐藏关键错误 | `_read_state_change_output` 过滤输出行，隐藏 Traceback | 改为显示所有输出行，按关键词自动标色 |
| BUG-07 | 多任务排队功能"丢失" | 批量任务面板在滚动区域下方，需滚动才能看到 | 重构为顶部左右两栏布局，批量任务移到序列号右侧 |
| BUG-08 | 状态一致时点击开始测试无反应 | `build_command()` 引用已删除的 `self.config_vars["precondition"]`，抛出 `KeyError` | 删除已移除变量引用，只保留 `_skip_precondition` 检查 |
| BUG-09 | start_test 未捕获异常导致静默失败 | 无外层异常捕获 | 包装为 `_start_test_internal()` + 外层 try/except，输出完整 Traceback |

## 6. 兼容性说明

### 6.1 向后兼容

- 所有 v1.9.1 的测试类（9个）保持不变，功能不受影响
- 命令行 `--perf-state fob` 和 `--perf-state steady` 行为不变
- 日志格式保持兼容
- 配置文件格式保持兼容

### 6.2 不兼容变更

| 变更 | 影响 | 迁移方式 |
|------|------|---------|
| `--perf-state both` 移除 | 依赖 both 模式批量测试的脚本需修改 | 改为分别执行 fob 和 steady 两次测试 |
| `--perf-state` 默认值从 both 改为 unknown | 默认行为从"先FOB后Steady"变为"直接测试" | 如需 FOB 测试显式指定 `--perf-state fob` |
| 稳态预处理算法变更 | 预处理时间从固定值变为动态检测（可能更长） | 可通过 `--steady-max-rounds` 和 `--steady-point-duration` 控制 |

### 6.3 环境依赖

- Python 3.10+（测试环境 3.10.12）
- `nvme-cli`（必须，用于 `nvme format --ses=1`）
- `fio`（建议 3.30+，使用 `json` 输出格式）
- Linux Ubuntu 22.04（测试环境）
- root 权限（nvme format 需要）

## 7. 升级指南

### 7.1 文件替换

```bash
# 备份旧版本
cp /home/test/max_tool/ssd_test_v1.9.1.py /home/test/max_tool/ssd_test_v1.9.1.py.bak

# 替换新版本

python3 /home/test/max_tool/ssd_test_v1.9.2.py --version
# 预期输出: ssd_test.py v1.9.2
```

### 7.2 典型使用流程

```bash
# 1. 进入 FOB 状态
sudo python3 /home/test/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 --action enter-fob -y

# 2. 查看状态
python3 /home/test/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 --action status

# 3. FOB 状态性能测试（状态一致，自动跳过擦除）
sudo python3 /home/test/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 --perf-state fob --test perf -y

# 4. 进入稳态
sudo python3 /home/test/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 --action enter-steady -y

# 5. 稳态性能测试
sudo python3 /home/test/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 --perf-state steady --test perf -y

# 6. Unknown 直接测试（不进入任何状态）
sudo python3 /home/test/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 --perf-state unknown --test perf -y
```

### 7.3 GUI 使用

1. 启动：`sudo python3 /home/test/max_tool/ssd_test_v1.9.2.py`
2. 选择设备 → 扫描设备
3. 查看顶部"SSD 状态控制"面板确认当前状态
4. 如需切换状态，点击"进入 FOB"或"进入稳态"
5. 选择测试项目 → 性能测试 → 选择目标状态（FOB/Steady/Unknown）
6. 点击"开始测试"

## 8. 已知限制

1. **稳态检测时间**：WDPC 最多25轮 × 3点 × 60秒 = 75分钟，实际通常5-15轮达标
2. **nvme format 支持**：部分老旧 SSD 不支持 `--ses=1`，会自动回退 blkdiscard（但 blkdiscard 不等同于真正 FOB）
3. **状态文件**：状态基于软件记录，非硬件读取；如果 SSD 被其他工具擦除/写入，状态可能不准确，需手动"重置 Unknown"
4. **多设备**：状态按序列号隔离，但 GUI 单次只操作一个设备
