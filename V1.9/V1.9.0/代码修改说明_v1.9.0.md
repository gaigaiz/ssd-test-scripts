# ssd\_test.py 代码修改说明（v1.8.5 → v1.9.0）

> 文档版本：v1.0 | 生成日期：2026-09-18 | 对应脚本：ssd_test_v1.9.0.py



***

## 1. 修改概述

本次修改在 **Normal Power Cycle Test（正常电源循环测试）** 模块中新增第三种电源控制模式 `enhanced`**（增强模式）**，同时完整保留原有的 `ipmi`（IPMI 远程自动断电上电）和 `manual`（手动断电上电）两种模式。用户可通过命令行参数 `--pc-power-mode` 或 GUI 上位机下拉框在三种模式间切换。

`enhanced` 模式融合了从 OKN 企业级 SSD 测试框架（`power_cycle_test.py`、`npor_test.py`、`spor_test.py`、`okn_common_function.py`）中学到的最佳实践，在原有 "混合读写 → 正常关机 → 断电 → 上电 → 检查" 流程基础上增加了三项核心增强：



1. **断电前 NVMe 优雅移除**（Shutdown Notification）—— 确保 SSD 固件完成缓存刷写后再断电

2. **循环前 Pattern 数据写入 + 循环后 LBA 级 Pattern 校验读**—— 比文件级 SHA-256 更严格的数据完整性检测

3. **PCIe Link 速率 / 宽度一致性校验 + 跨循环统计**—— 捕获掉盘后降速 / 降宽等隐性问题



***

## 2. 三种模式对比



| 测试步骤        | ipmi 模式                                 | manual 模式              | enhanced 模式                                                                     |
| ----------- | --------------------------------------- | ---------------------- | ------------------------------------------------------------------------------- |
| 循环前数据准备     | 写完整性测试文件（SHA-256 基准）                    | 同左                     | 写完整性测试文件 **+ 写入已知 Pattern 数据到裸设备（默认 20GB，Pattern=0xAA）**                        |
| 循环前 Link 记录 | 无                                       | 无                      | **记录初始 PCIe Link 宽度 / 速率**                                                      |
| 循环中负载       | fio 混合读写（randrw 70/30）                  | 同左                     | 同左                                                                              |
| 断电前操作       | sync → shutdown -h now                  | sync → shutdown -h now | **sync → umount → nvme disconnect（Shutdown Notification）→ 等待设备节点消失 → shutdown** |
| 断电方式        | IPMI 远程自动断电→延时→上电                       | 手动断电上电                 | 指定 ipmi-host 时复用 IPMI；未指定时走手动断电上电                                               |
| 开机后检查       | 磁盘枚举 + 分区表 + fsck + SHA-256 完整性 + SMART | 同左                     | **磁盘枚举 + 分区表 + fsck + Pattern LBA 级校验 + PCIe Link 一致性校验 + SMART**               |
| Link 统计     | 无                                       | 无                      | **跨循环维护 width\_stats /speed\_stats 计数器**                                        |
| 最终功能测试      | 完整功能测试（识别 / SMART / 性能 / 读写）            | 同左                     | 同左                                                                              |

### 3.3 PowerCycleTester 类 — 新增 5 个方法

**变更类型**：新增（不修改任何现有方法）

在 `run_final_functional_test()` 方法之后、`run()` 方法之前插入以下 5 个方法：

#### 3.3.1 `nvme_graceful_remove(self) -> Tuple[bool, str]`



* **功能**：断电前执行 NVMe 优雅移除，向 SSD 控制器发送 Shutdown Notification

* **流程**：`sync` → `umount` 测试分区 → `nvme disconnect /dev/nvmeX` → 等待设备节点消失（超时 30s）

* **容错**：`nvme disconnect` 失败时降级为仅 umount+sync，不中断测试；设备节点 30s 内未消失时记录 warning 后继续

* **参考来源**：OKN `link_state.remove_device()` / `power_down(safe_shutdown=True)`

#### 3.3.2 `write_pattern_data(self, state) -> Tuple[bool, Dict]`



* **功能**：循环前向裸设备写入已知 Pattern 数据，作为 LBA 级校验基准

* **实现**：使用 fio `--rw=write --bs=128k --iodepth=256 --buffer_pattern=<pattern> --size=<size_bytes>` 直接写入裸设备（绕过文件系统）

* **状态记录**：将 pattern、size\_bytes、written\_bytes、lba\_start 写入 `state["enhanced_pattern"]`

* **参考来源**：OKN `npor_test.py` 顺序写 + RANDOM\_LBA pattern

#### 3.3.3 `verify_pattern_data(self, state) -> Tuple[bool, Dict]`



* **功能**：循环后校验 Pattern 数据，逐块比对写入的 Pattern

* **实现**：使用 fio `--rw=read --bs=128k --verify=pattern --verify_pattern=<pattern> --do_verify=1` 校验读

* **输出**：total\_blocks、verified\_blocks、mismatch\_blocks

* **容错**：fio JSON 解析失败时 fallback 到文本匹配（检测 "mismatch" / "verification failed"）

* **参考来源**：OKN `npor_test.py` `verify_read(do_data_compare=True, verify_pattern=True)`

#### 3.3.4 `check_pcie_link_state(self, state) -> Tuple[bool, Dict]`



* **功能**：校验当前 PCIe Link 宽度 / 速率与初始值一致，并维护跨循环统计

* **实现**：


  * 优先通过 sysfs 读取 `/sys/bus/pci/devices/<bdf>/current_link_width` 和 `current_link_speed`

  * Fallback 到 `nvme get-phy <ctrl> -o json`

  * 首次调用时记录初始状态到 `state["enhanced_initial_link"]`

  * 维护 `state["enhanced_link_width_stats"]` 和 `enhanced_link_speed_stats` 计数器字典

* **容错**：两种方式均无法获取 Link 状态时跳过校验并记录 warning，不判 FAIL；`--pc-no-link-check` 可完全禁用

* **参考来源**：OKN `check_pcie_link()` + width\_qty/speed\_qty 统计机制

#### 3.3.5 `enhanced_post_cycle_check(self, state) -> Tuple[bool, Dict]`



* **功能**：enhanced 模式开机后的完整综合检查（6 项）

* **检查项**：

1. 磁盘枚举（设备节点存在）

2. 分区表检查（parted print，检测 gpt/msdos）

3. 文件系统检查（fsck -n 只读检查，检查后重新挂载）

4. **Pattern 数据完整性校验**（调用 `verify_pattern_data`）

5. **PCIe Link 一致性校验**（调用 `check_pcie_link_state`）

6. SMART 检查（nvme smart-log：介质错误数、温度；或 smartctl -H）

* **返回**：all\_ok（6 项全部通过）+ 详细结果字典

## 4. 兼容性说明

### 4.1 向后兼容



* **默认行为不变**：`--pc-power-mode` 默认值仍为 `ipmi`，不传该参数时行为与 v1.8.5 完全一致

* **ipmi/manual 路径不变**：两种模式的执行代码逐行保持原样，仅通过 `if/elif/else` 分支与 enhanced 模式隔离

* **新参数有默认值**：所有新增命令行参数和 TestConfig 字段均有合理默认值，旧的调用方式不受影响

* **其他测试项不受影响**：固件、SMART、容量、性能、SPOR、OSINT、读写等测试项的代码完全未改动

### 4.2 状态文件兼容



* enhanced 模式新增的 state 字段（`enhanced_pattern`、`enhanced_initial_link`、`enhanced_link_width_stats`、`enhanced_link_speed_stats`）使用 `state.setdefault()` 或直接赋值方式读取 / 写入

* 旧状态文件（ipmi/manual 模式产生的）可正常加载，enhanced 字段缺失时自动初始化

* 建议不同模式使用不同的 `--pc-state-file` 路径，避免状态混淆

* 不使用 Python 3.10+ 专属语法（如 match-case、PEP 604 联合类型运算符 `X | Y`）

## 5. 已知限制



1. `nvme disconnect`**&#x20;兼容性**：部分 NVMe 驱动器或内核版本可能不支持 `nvme disconnect` 命令。代码已做降级处理（失败时仅 umount+sync），但优雅移除效果会降低。建议使用内核 5.15+ 和 nvme-cli 1.16+。

2. **fio verify 参数版本差异**：`--verify=pattern` 在不同 fio 版本中语法可能有差异。代码优先使用 JSON 输出解析，失败时 fallback 到文本匹配。建议使用 fio 3.25+。

3. **Pattern 写入耗时**：enhanced 模式在 setup 阶段需要写入指定 GB 量的 Pattern 数据（默认 20GB），耗时取决于盘性能。对于低速盘或大容量配置，建议适当减小 `--pc-pattern-size-gb`。

4. **PCIe Link 信息获取**：sysfs 路径在不同内核版本 / 平台上可能有差异。代码已做双重 fallback（sysfs → nvme get-phy），均失败时跳过 Link 校验。

5. **enhanced + 无 ipmi-host**：enhanced 模式未指定 ipmi-host 时，断电上电需要手动操作（与 manual 模式相同），仅断电前增加了 NVMe 优雅移除步骤。

6. **本电脑不负责测试**：所有代码修改在 Windows 本机完成，未在 Linux 目标环境执行实际测试。首次使用前建议在测试环境进行小规模验证（如 `--pc-cycles 2`）。
