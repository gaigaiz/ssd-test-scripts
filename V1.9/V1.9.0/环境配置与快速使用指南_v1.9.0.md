## 4. 三种电源控制模式快速上手

### 4.1 ipmi 模式（IPMI 远程自动断电上电）

**适用场景**：测试机配备 IPMI BMC，可通过网络远程控制电源，实现完全自动化的电源循环测试。

**前置条件**：
- IPMI BMC 地址、用户名、密码已知
- 测试机与 BMC 网络可达
- ipmitool 已安装

**快速命令**：

```bash
# 基本用法：10 次循环，IPMI 远程断电
sudo python3 ssd_test.py -d /dev/nvme0n1 -t powercycle \
    --pc-cycles 10 \
    --pc-power-mode ipmi \
    --ipmi-host 192.168.1.100 \
    --ipmi-user ADMIN \
    --ipmi-pass ADMIN \
    -y

# 自定义循环参数：20 次循环，每次混合读写 60 秒，断电间隔 15 秒
sudo python3 ssd_test.py -d /dev/nvme0n1 -t powercycle \
    --pc-cycles 20 \
    --pc-power-mode ipmi \
    --ipmi-host 192.168.1.100 \
    --pc-rw-duration 60 \
    --pc-off-interval 15 \
    -y
```

### 4.2 manual 模式（手动断电上电）

**适用场景**：测试机无 IPMI，或需要人工控制断电时机（如配合电源开关、PDU 手动操作）。

**前置条件**：
- 测试人员可物理接触电源开关或 PDU
- 脚本关机后，人工执行断电→等待→上电操作

**快速命令**：

```bash
# 基本用法：5 次循环，手动断电上电
sudo python3 ssd_test.py -d /dev/nvme0n1 -t powercycle \
    --pc-cycles 5 \
    --pc-power-mode manual \
    -y

# 脚本会在关机后提示手动断电上电，上电后系统重启，脚本通过状态文件自动恢复
```

**操作流程**：
1. 启动脚本，脚本执行混合读写负载
2. 脚本执行 `shutdown -h now`，系统关机
3. **人工操作**：关闭电源 → 等待 10-30 秒 → 打开电源
4. 系统启动，脚本通过开机自启或手动重新运行恢复执行
5. 脚本检测到状态文件，执行开机检查
6. 重复步骤 1-5 直到完成指定循环次数

### 4.3 enhanced 模式（增强模式）

**适用场景**：需要更严格的电源循环测试，包括 NVMe 优雅移除、LBA 级数据完整性校验、PCIe Link 状态监控。适用于企业级 SSD 验证、固件稳定性测试、数据保持力测试。

**前置条件**：
- nvme-cli 1.16+（支持 `nvme disconnect`）
- fio 3.25+（支持 `--verify=pattern`）
- 内核 5.15+（sysfs PCIe Link 信息更完整）
- 可选：指定 ipmi-host 实现自动断电上电

**快速命令**：

```bash
# 用法1：enhanced + 手动断电上电（无 IPMI）
sudo python3 ssd_test.py -d /dev/nvme0n1 -t powercycle \
    --pc-power-mode enhanced \
    --pc-pattern 0xAA \
    --pc-pattern-size-gb 20 \
    -y

# 用法2：enhanced + IPMI 自动断电上电（推荐）
sudo python3 ssd_test.py -d /dev/nvme0n1 -t powercycle \
    --pc-power-mode enhanced \
    --ipmi-host 192.168.1.100 \
    --pc-pattern-size-gb 20 \
    -y

# 用法3：enhanced + 禁用 PCIe Link 校验（某些平台 Link 信息不可用时）
sudo python3 ssd_test.py -d /dev/nvme0n1 -t powercycle \
    --pc-power-mode enhanced \
    --pc-pattern-size-gb 10 \
    --pc-no-link-check \
    -y

# 用法4：小规模验证（首次使用建议先跑 2 次循环）
sudo python3 ssd_test.py -d /dev/nvme0n1 -t powercycle \
    --pc-power-mode enhanced \
    --ipmi-host 192.168.1.100 \
    --pc-cycles 2 \
    --pc-pattern-size-gb 5 \
    -y
```

**enhanced 模式测试流程**：
1. **Setup 阶段**：
   - 创建测试分区和文件系统
   - 写入完整性测试文件（SHA-256 基准）
   - **写入已知 Pattern 数据到裸设备**（默认 20GB，Pattern=0xAA，bs=128k，QD=256）
   - **记录初始 PCIe Link 宽度/速率**
2. **每次循环**：
   - 启动 fio 混合读写负载（持续指定秒数）
   - 停止混合读写
   - **执行 NVMe 优雅移除**：sync → umount → nvme disconnect → 等待设备节点消失
   - 保存状态文件
   - 断电（IPMI 自动或手动）→ 延时 → 上电
3. **开机后检查**：
   - 重新挂载分区
   - 磁盘枚举检查
   - 分区表检查
   - 文件系统 fsck 检查
   - **Pattern 数据 LBA 级校验读**（fio verify=pattern，统计 mismatch 块数）
   - **PCIe Link 一致性校验**（与初始值比对，维护跨循环统计）
   - SMART 检查（介质错误数、温度）
4. **最终功能测试**：完整功能测试（设备识别、SMART、性能、读写）

## 5. GUI 上位机使用

### 5.1 启动 GUI

```bash
sudo python3 ssd_test.py --gui
```

> 注意：GUI 需要图形界面环境（X11 / Wayland）。SSH 远程运行时需要 X11 转发（`ssh -X`）或 VNC。

### 5.2 正常电源循环标签页操作

1. 点击"正常电源循环"标签页
2. 设置"循环次数"（默认 10）
3. 在"电源控制模式"下拉框中选择：
   - `ipmi` — IPMI 远程自动断电上电
   - `manual` — 手动断电上电
   - `enhanced` — 增强模式（选择后下方专属控件自动启用）
4. 如选择 ipmi 或 enhanced+IPMI，填写 IPMI 主机、用户名、密码
5. 设置"断电间隔(秒)"和"读写持续(秒)"
6. **enhanced 模式专属**（仅选择 enhanced 时可用）：
   - "数据 Pattern"：默认 "0xAA"，可修改为其他十六进制值（如 "0x55"、"0x00"、"0xFF"）
   - "Pattern写入量(GB)"：默认 20，范围 1-500
   - "PCIe Link校验"：默认勾选，取消勾选等价于 `--pc-no-link-check`
7. 返回"基本配置"标签页，选择测试设备和测试项
8. 点击"生成命令"查看生成的命令行
9. 点击"开始测试"执行

## 6. enhanced 模式参数详解

| 参数 | 命令行 | GUI 控件 | 默认值 | 说明 |
|------|--------|---------|-------|------|
| 电源控制模式 | `--pc-power-mode enhanced` | 电源控制模式下拉框 | ipmi | 选择 enhanced 启用增强模式 |
| 数据 Pattern | `--pc-pattern 0xAA` | 数据 Pattern Entry | 0xAA | 写入裸设备的 fio buffer_pattern，建议使用交替位模式（0xAA/0x55）以最大化信号完整性检测能力 |
| Pattern 写入量 | `--pc-pattern-size-gb 20` | Pattern写入量(GB) Spinbox | 20 | 写入裸设备的数据量，越大校验覆盖越广但 setup 耗时越长。建议为盘容量的 5%-20% |
| PCIe Link 校验 | `--pc-no-link-check`（禁用） | PCIe Link校验 Checkbutton | 启用 | 启用后每次循环后比对 PCIe Link 宽度/速率与初始值，并维护跨循环统计。某些平台 Link 信息不可用时可禁用 |

### 6.1 Pattern 选择建议

| Pattern | 适用场景 |
|---------|---------|
| 0xAA (10101010) | 默认，交替位模式，对信号完整性问题敏感 |
| 0x55 (01010101) | 与 0xAA 互补，可交替使用以覆盖不同信号路径 |
| 0x00 (00000000) | 全零，检测 stuck-at-1 故障 |
| 0xFF (11111111) | 全一，检测 stuck-at-0 故障 |
| 0xCC (11001100) | 混合模式，模拟真实数据分布 |

## 7. 状态文件与断点恢复机制

### 7.1 状态文件位置

默认路径：`/var/lib/ssd_power_cycle_state.json`

可通过 `--pc-state-file` 参数自定义：

```bash
sudo python3 ssd_test.py -d /dev/nvme0n1 -t powercycle \
    --pc-state-file /var/lib/ssd_test/pc_enhanced_state.json \
    --pc-power-mode enhanced -y
```

### 7.2 状态文件内容

状态文件以 JSON 格式存储，包含以下关键字段：

| 字段 | 说明 |
|------|------|
| `phase` | 当前阶段：setup / rw_load / boot_check / final_test / done |
| `current_cycle` | 当前循环次数 |
| `target_cycles` | 目标循环次数 |
| `cycle_results` | 每次循环的检查结果列表 |
| `integrity_files` | 完整性测试文件的 SHA-256 基准 |
| `enhanced_pattern` | enhanced 模式：Pattern 信息（pattern、size_bytes、written_bytes、lba_start） |
| `enhanced_initial_link` | enhanced 模式：初始 PCIe Link 宽度/速率 |
| `enhanced_link_width_stats` | enhanced 模式：跨循环 Link 宽度统计 |
| `enhanced_link_speed_stats` | enhanced 模式：跨循环 Link 速率统计 |

### 7.3 断点恢复

脚本在每次关机前将状态写入状态文件。系统重启后，重新运行相同命令即可自动从断点恢复：

```bash
# 重启后恢复执行（使用与之前相同的参数）
sudo python3 ssd_test.py -d /dev/nvme0n1 -t powercycle \
    --pc-power-mode enhanced \
    --ipmi-host 192.168.1.100 \
    -y
```

脚本会检测到状态文件中的 `phase=boot_check`，自动执行开机检查，然后继续下一循环。

### 7.4 重置测试

如需从头开始测试，删除状态文件即可：

```bash
sudo rm -f /var/lib/ssd_power_cycle_state.json
```

## 8. 日志与报告

### 8.1 日志输出位置

- **控制台输出**：实时显示测试进度和检查结果
- **日志文件**：`./logs/ssd_test_YYYYMMDD_HHMMSS.log`（脚本运行目录下的 logs 文件夹）
- **verbose 模式**：添加 `-v` 参数输出更详细的调试信息

### 8.2 测试报告

测试完成后，脚本输出结构化结果，包含：

- 测试状态（PASS / FAIL / ERROR / SKIP）
- 总循环次数
- 每次循环的检查结果（enhanced 模式包含 Pattern 校验结果和 Link 校验结果）
- 最终功能测试结果
- 失败详情（如有）

enhanced 模式的循环结果中额外包含：
- `pattern_integrity_ok`：Pattern 数据校验是否通过
- `pcie_link_ok`：PCIe Link 一致性是否通过
- `details.pattern_verify`：Pattern 校验详细信息（total_blocks、mismatch_blocks）
- `details.pcie_link`：Link 校验详细信息（当前/初始宽度速率、跨循环统计）

## 9. 常见问题排查

### 9.1 设备找不到

**现象**：报错 "设备 /dev/nvme0n1 不存在"

**排查步骤**：
```bash
# 查看 NVMe 设备列表
sudo nvme list
# 查看块设备
lsblk
# 查看 PCIe 设备
lspci | grep -i nvme
```

**解决**：使用 `nvme list` 输出中的正确设备路径（如 `/dev/nvme1n1`）。

### 9.2 IPMI 连接失败

**现象**：ipmitool 报错 "Error: Unable to establish IPMI v2 / RMCP+ session"

**排查步骤**：
```bash
# 测试 IPMI 连通性
ipmitool -H 192.168.1.100 -U ADMIN -P ADMIN -I lanplus chassis status
# 检查网络连通
ping 192.168.1.100
```

**解决**：确认 BMC 地址、用户名、密码正确；确认网络可达；确认 BMC 已启用 lanplus 接口。

### 9.3 enhanced 模式 Pattern 校验失败

**现象**：开机检查时 "Pattern 数据完整性: FAIL"，mismatch_blocks > 0

**可能原因**：
1. SSD 在断电时未完成缓存刷写（nvme disconnect 失败或不支持）
2. SSD 存在数据保持力问题
3. fio verify 参数与当前 fio 版本不兼容

**排查步骤**：
```bash
# 检查 nvme disconnect 是否支持
sudo nvme disconnect /dev/nvme0
# 检查 fio 版本
fio --version
# 手动执行 Pattern 写入和校验（单步验证）
sudo fio --name=test --filename=/dev/nvme0n1 --rw=write --bs=128k --size=1G --buffer_pattern=0xAA
sudo fio --name=test --filename=/dev/nvme0n1 --rw=read --bs=128k --size=1G --verify=pattern --verify_pattern=0xAA --do_verify=1
```

### 9.4 PCIe Link 校验失败或无法获取

**现象**："无法获取 PCIe Link 状态" 或 "PCIe Link 宽度/速率变化"

**排查步骤**：
```bash
# 检查 sysfs 路径
find /sys/bus/pci/devices/ -name "current_link_width" 2>/dev/null
# 检查 nvme get-phy
sudo nvme get-phy /dev/nvme0 -o json
```

**解决**：
- 如两种方式均无法获取，使用 `--pc-no-link-check` 禁用 Link 校验
- 如 Link 确实发生降速/降宽，检查 PCIe 插槽、线缆、散热是否正常

### 9.5 状态文件导致无法重新开始

**现象**：每次运行都从 boot_check 阶段恢复，无法重新 setup

**解决**：删除状态文件
```bash
sudo rm -f /var/lib/ssd_power_cycle_state.json
```

### 9.6 关机后脚本未自动恢复

**现象**：系统重启后脚本未自动运行

**解决**：需要配置开机自启，或手动重新运行相同命令。脚本设计为通过状态文件恢复，不依赖特定的自启机制。

可配置 systemd 服务实现自动恢复：
```bash
sudo tee /etc/systemd/system/ssd-test-resume.service << 'EOF'
[Unit]
Description=SSD Power Cycle Test Resume
After=multi-user.target

[Service]
Type=oneshot
ExecStart=/usr/bin/python3 /opt/ssd_test/ssd_test.py -d /dev/nvme0n1 -t powercycle --pc-power-mode enhanced --ipmi-host 192.168.1.100 -y
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable ssd-test-resume.service
```

### 9.7 GUI 无法启动

**现象**：报错 "no display name and no $DISPLAY environment variable"

**解决**：
- 本地运行：确保在图形界面终端中执行
- SSH 远程：使用 `ssh -X user@host` 启用 X11 转发
- 无图形环境：使用命令行模式（不加 `--gui`）
