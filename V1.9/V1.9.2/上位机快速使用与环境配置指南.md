# SSD 测试上位机快速使用与环境配置指南

> 版本：v1.9.2 | 适用系统：Ubuntu 22.04 | Python：3.10.12
> 脚本路径：`~/max_tool/ssd_test_v1.9.2.py`

---

## 1. 环境配置

### 1.1 系统要求

| 项目 | 要求 |
|-----|------|
| 操作系统 | Ubuntu 22.04 LTS (x86_64) |
| Python | 3.10.12 或更高 |
| 权限 | root / sudo（nvme format、fio裸盘测试需要） |
| 磁盘 | NVMe SSD（如 /dev/nvme0n1） |

### 1.2 安装依赖

```bash
# 更新软件源
sudo apt update

# 安装系统依赖
sudo apt install -y python3 python3-pip python3-tk nvme-cli fio smartmontools util-linux

# 验证安装
python3 --version          # 应显示 Python 3.10.x
nvme --version             # 应显示 nvme-cli 版本
fio --version              # 应显示 fio 版本
smartctl --version         # 应显示 smartmontools 版本
```

### 1.3 部署脚本

```bash
# 创建目录
mkdir -p ~/max_tool

# 将脚本复制到目标路径（从Windows拷贝或直接创建）
cp /path/to/ssd_test_v1.9.2.py ~/max_tool/

# 验证脚本存在
ls -la ~/max_tool/ssd_test_v1.9.2.py

# 语法检查
python3 -m py_compile ~/max_tool/ssd_test_v1.9.2.py
echo "语法检查通过"

# 查看版本
python3 ~/max_tool/ssd_test_v1.9.2.py --version
# 应显示: ssd_test.py v1.9.2
```

### 1.4 创建工作目录

```bash
# 报告和日志目录（脚本会自动创建，也可手动创建）
mkdir -p ~/max_tool/reports
mkdir -p ~/max_tool/logs
```

## 2. 快速启动

### 2.1 启动 GUI 上位机（推荐）

```bash
sudo python3 ~/max_tool/ssd_test_v1.9.2.py --gui
```

> **重要**：必须使用 `sudo` 启动，否则 nvme format 和裸盘 fio 测试会因权限不足失败。

### 2.2 命令行模式（无GUI）

```bash
# 查看帮助
sudo python3 ~/max_tool/ssd_test_v1.9.2.py --help

# 执行全部测试
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 -t all -y

# 仅执行性能测试（FOB状态）
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 -t perf --perf-state fob -y

# 仅执行性能测试（稳态）
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 -t perf --perf-state steady -y
```

### 3.2 性能标签页 - SSD 状态控制面板（v1.9.2 新增）

在"性能"标签页顶部，新增了 **SSD 状态控制** 面板：

```
┌─ SSD 状态控制 ─────────────────────────────────────────────┐
│ 当前 SSD 状态: [  FOB  ]  序列号: XXX123 | 更新时间: ...   │
│                                                             │
│ [进入 FOB 状态] [进入稳态(Steady)] [刷新状态] [重置为Unknown]│
└─────────────────────────────────────────────────────────────┘
```

#### 状态说明

| 状态 | 颜色 | 含义 |
|-----|------|------|
| UNKNOWN | 灰色 | 初始状态，未经过任何状态进入操作 |
| FOB | 蓝色 | 已通过 NVMe User Data Erase 进入出厂空白状态 |
| STEADY | 绿色 | 已通过 WIPC+WDPC 进入稳态 |

#### 按钮功能

| 按钮 | 功能 | 耗时 |
|-----|------|------|
| 进入 FOB 状态 | 执行 `sudo nvme format --ses=1` 擦除全盘 | 10秒-2分钟 |
| 进入稳态(Steady) | 执行 WIPC顺序写2遍 + WDPC多轮稳态检测 | 30-90分钟 |
| 刷新状态 | 从状态文件重新读取并显示当前状态 | 即时 |
| 重置为Unknown | 仅更新状态记录为Unknown，不操作设备 | 即时 |

> **注意**：点击"进入 FOB 状态"或"进入稳态"后，会弹出确认对话框。确认后通过子进程执行，期间GUI可能短暂无响应，日志区域会输出执行进度。

### 3.3 开始测试 - 三分支状态逻辑（v1.9.2 新增）

选择"性能"测试项并点击"开始测试"时，系统会自动判断当前SSD状态与性能测试目标状态：

#### 分支A：当前状态为 Unknown
- **行为**：直接进行性能测试，不进入任何状态
- **日志**：`当前 SSD 状态为 Unknown，将直接进行性能测试（不进入任何状态）`

#### 分支B：当前状态与目标状态一致
- **行为**：直接进行性能测试，不重复进入状态
- **示例**：当前状态=FOB，性能测试选择=FOB
- **日志**：`当前 SSD 状态(FOB)与目标状态(FOB)一致，直接进行性能测试（不重复进入）`

#### 分支C：当前状态与目标状态不一致
- **行为**：弹出警告对话框，用户选择：
  - **"是"**：自动先进入目标状态，完成后再进行性能测试
  - **"否"**：取消测试，请手动控制SSD状态后重试
- **示例**：当前状态=Steady，性能测试选择=FOB
- **警告内容**：
  ```
  SSD 目前状态与目标状态不一致！

  当前状态: STEADY
  目标状态: FOB

  请确认是否直接进入 FOB 状态再执行后续测试？

  选择[是]: 自动进入目标状态后再进行性能测试
  选择[否]: 取消测试，请手动控制 SSD 状态后重试
  ```

#### perf_state=both 的特殊处理
- 目标状态判定为 **FOB**（先执行FOB测试，再执行Steady测试）
- 如当前状态=Steady，会按分支C处理，提示先进入FOB

## 4. 命令行高级用法

### 4.1 v1.9.2 新增命令行参数

| 参数 | 默认值 | 说明 |
|-----|-------|------|
| `--action` | run-tests | 动作类型：run-tests/enter-fob/enter-steady/status |
| `--purge-method` | auto | FOB擦除方式：auto/user-data/blkdiscard |
| `--steady-max-rounds` | 25 | WDPC稳态检测最大轮数 |
| `--steady-point-duration` | 60 | WDPC每个测试点运行秒数 |
| `--smart-ignore-media-errors` | 5353 | SMART检查忽视的介质错误ID（逗号分隔） |

### 4.2 状态管理命令

```bash
# 查询当前SSD状态
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 --action status
# 输出: SSD_STATE: fob / steady / unknown

# 仅进入FOB状态（不执行性能测试）
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 --action enter-fob -y

# 仅进入稳态（不执行性能测试）
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 --action enter-steady -y

# 进入稳态，使用快速参数（10轮，每点30秒）
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 --action enter-steady \
    --steady-max-rounds 10 --steady-point-duration 30 -y
```

### 4.3 FOB擦除方式控制

```bash
# 自动模式（默认）：优先NVMe Format --ses=1，失败回退blkdiscard
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 -t perf --perf-state fob -y

# 强制仅使用NVMe User Data Erase（失败则报错）
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 -t perf --perf-state fob \
    --purge-method user-data -y

# 强制仅使用blkdiscard
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 -t perf --perf-state fob \
    --purge-method blkdiscard -y
```

### 4.4 稳态预处理参数调优

```bash
# 标准模式（默认）：最多25轮，每点60秒
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 -t perf --perf-state steady -y

# 快速模式：最多10轮，每点30秒（适合验证流程）
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 -t perf --perf-state steady \
    --steady-max-rounds 10 --steady-point-duration 30 -y

# 跳过稳态预处理（直接测试，不保证稳态）
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 -t perf --perf-state steady \
    --no-precondition -y
```

### 4.5 试运行模式（不实际执行）

```bash
# 仅打印命令，不实际执行（用于验证参数）
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 -t perf --perf-state fob \
    --dry-run -y
```

## 5. FOB 与稳态进入流程详解

### 5.1 FOB 状态进入流程

```
开始
  │
  ▼
执行 NVMe Format --ses=1 (User Data Erase)
  │
  ├─ 成功 ──► 等待10秒 ──► 更新状态文件为FOB ──► 完成
  │
  └─ 失败 ──► 回退 blkdiscard
                │
                ├─ 成功 ──► 等待10秒 ──► 更新状态文件为FOB ──► 完成
                │
                └─ 失败 ──► 记录错误，继续测试（状态不可靠）
```

**关键命令**：
```bash
sudo nvme format /dev/nvme0n1 --namespace-id=1 --ses=1
```

### 5.2 稳态进入流程（SNIA SSS PTS v2.0.2 近似）

```
开始
  │
  ▼
WIPC: 顺序写满全盘 2 次 (128K QD32)
  │
  ▼
WDPC 循环（最多25轮）:
  ├─ 轮次1: RND4K写(60s) → RND64K混合65(60s) → RND1024K读(60s)
  ├─ 轮次2: 同上
  ├─ ...
  ├─ 轮次5+: 每轮后检测稳态
  │   ├─ 3个跟踪变量均满足: Range≤20%×Ave 且 Slope≤10%×Ave
  │   │   └─ 达到稳态 ──► 更新状态文件为Steady ──► 完成
  │   └─ 未达到稳态 ──► 继续下一轮
  │
  └─ 达到25轮仍未稳态 ──► 降级继续（告警）──► 更新状态文件为Steady ──► 完成
```

**稳态判定标准**（5轮滑动窗口）：
- Range = (最大值 - 最小值) ≤ 20% × 平均值
- Slope = |最小二乘斜率| ≤ 10% × 平均值
- 3个跟踪变量**同时**满足才判定为稳态

**3个跟踪变量**：
| 变量名 | 模式 | 块大小 | 队列深度 | 读占比 |
|-------|------|-------|---------|-------|
| RND4K_Write | randwrite | 4K | 32 | - |
| RND64K_Mix65 | randrw | 64K | 32 | 65% |
| RND1024K_Read | randread | 1024K | 32 | - |

## 8. 常见问题

### Q1: 启动GUI时提示"需要root权限"

**A**: 必须使用 `sudo` 启动：
```bash
sudo python3 ~/max_tool/ssd_test_v1.9.2.py --gui
```

### Q2: 点击"进入FOB状态"后失败

**A**: 检查以下几点：
1. 设备是否支持 NVMe Format：`sudo nvme id-ctrl /dev/nvme0 | grep -i ses`
2. 是否使用sudo启动
3. 查看日志文件中的具体错误信息
4. 可尝试 `--purge-method blkdiscard` 使用回退方式

### Q3: 稳态预处理时间太长

**A**: 使用快速参数：
```bash
sudo python3 ~/max_tool/ssd_test_v1.9.2.py -d /dev/nvme0n1 --action enter-steady \
    --steady-max-rounds 10 --steady-point-duration 30 -y
```

### Q4: GUI显示状态不正确

**A**: 点击"刷新状态"按钮，或检查状态文件：
```bash
cat ~/.ssd_test_state.json
```
如状态文件损坏，删除后重启GUI：
```bash
rm ~/.ssd_test_state.json
```

### Q5: 性能测试时状态不一致警告

**A**: 这是v1.9.2的保护机制。选择：
- **"是"**：自动先进入目标状态再测试（推荐）
- **"否"**：取消，手动点击"进入FOB/稳态"按钮后再测试

### Q6: 脚本路径错误

**A**: 确保脚本在 `~/max_tool/ssd_test_v1.9.2.py`：
```bash
ls -la ~/max_tool/ssd_test_v1.9.2.py
```
如不在该路径，需复制到该路径，或修改代码中的脚本路径引用。

### Q7: 其他测试项（固件/SMART/容量等）是否受影响

**A**: 不受影响。v1.9.2仅修改了性能测试模块和GUI，其他7个测试类代码完全未改动。

## 9. 版本对比

| 特性 | v1.9.1 | v1.9.2 |
|-----|--------|--------|
| FOB擦除方式 | blkdiscard (TRIM) | NVMe Format --ses=1 (User Data Erase) + blkdiscard回退 |
| 稳态预处理 | 固定写入量(顺序2遍+随机2X+等300s) | WIPC + WDPC多轮循环 + 5轮滑动窗口稳态检测 |
| SSD状态显示 | 无 | GUI状态面板 (Unknown/FOB/Steady) |
| 手动状态切换 | 无 | GUI按钮 (进入FOB/进入稳态/刷新/重置) |
| 开始测试状态逻辑 | 无条件进入状态 | 三分支逻辑 (Unknown直接测/一致直接测/不一致警告) |
| SMART介质错误忽视 | 无 | 性能测试中可配置忽视ID (默认5353) |
| 状态持久化 | 无 | ~/.ssd_test_state.json |
| 命令行--action | 无 | run-tests/enter-fob/enter-steady/status |
